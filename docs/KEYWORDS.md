# Руководство по Keyword API v2 — управление поведением суммонов через кейворды

**Summon Control Framework (SCF)** предоставляет декларативный **Zero-Master Keyword API v2**, позволяющий модмейкерам и игрокам тонко настраивать поведение отдельных призванных существ, заклинаний призыва и произвольных NPC с помощью стандартных записей Skyrim `KYWD` — **без зависимости от мастер-файла `SummonControlFramework.esp`** и без написания Papyrus-скриптов.

---

## 1. Как это работает (Zero-Master принцип)

1. **Мастер-файл не требуется.** Создайте запись `KYWD` с нужным `EditorID` в любом плагине (Creation Kit / xEdit) либо возьмите уже существующую запись из любого мода в порядке загрузки.
2. **Регистр не важен.** `SCF_HighThreat`, `scf_highthreat` и `SCF_HIGHTHREAT` эквивалентны.
3. **Несколько плагинов не конфликтуют.** Если два разных мода объявили собственные `KYWD` с одинаковым `EditorID` (например, оба создали `SCF_Stationary`), SCF на этапе `kDataLoaded` собирает **все** `TESForm*` с совпадающим `EditorID` и распознаёт любой из них.
4. **Нулевые накладные расходы, если кейворды не используются:**
   * Мировое сканирование (коллизии, угроза, friendly fire, авторегистрация) **полностью отключено**, если в порядке загрузки нет ни одного мирового кейворда (`WorldActive() == false`).
   * Профилирование суммонов **полностью отключено**, если в порядке загрузки нет ни одного кейворда `SCF_*` (`SummonActive() == false`).
5. **100% обратная совместимость** с Keyword API v1 (`SCF_PassThroughFriends`, `SCF_PassThroughAll`, `SCF_Untargetable`) и с кейвордами **Summon Combat Radius** (`aaMZkw_SummonCombatArea200`, `aaMZkw_SummonCombatArea500`, `aaMZkw_SummonCombatArea1000`).

## 2. Куда вешать кейворды и область действия (Scope)

### Источники, из которых SCF читает кейворды

| Источник | Как работает | Поддержка |
|---|---|---|
| **База актёра (`NPC_`)** | Постоянное свойство конкретного существа (через CK, xEdit или **KID**). | Все кейворды |
| **Раса (`RACE`)** | Постоянное свойство целой расы (например, все призраки или все атронахи). | Все кейворды |
| **Активный магический эффект (`MGEF`) на актёре** | Динамическое правило: действует ровно пока бафф/способность/зачарование активно (удобно для временных таунтов, неуязвимости, баффов скорости через **SPID** или заклинания). | Все кейворды |
| **Исходный `MGEF` заклинания призыва** (`ActiveEffect::GetBaseObject()` на игроке) | Позволяет настроить поведение **конкретного заклинания призыва**, не редактируя запись самого `NPC_`. Одно и то же существо, призванное двумя разными заклинаниями, может вести себя по-разному. | Все кейворды на суммонах игрока (включая `SCF_FreeSlot`, `SCF_Persistent`, `SCF_NoPersistence`, угрозу, friendly fire и пасс-тру) |

> **Важно для `SCF_FreeSlot` / `SCF_IgnoreLimit`:** хук лимита движка (`SummonLimit`) срабатывает **в момент каста заклинания**, ещё до появления нового актёра в реестре. Чтобы новый суммон не вытеснил уже существующего при касте, вешайте `SCF_FreeSlot` на **магический эффект (`MGEF`) заклинания призыва** (рекомендуется) — тогда движок пропустит проверку лимита и при касте, и в реестре SCF.

### Два уровня области действия

* **World (мировые кейворды)** — работают на **любом загруженном живом актёре** в высоком процессе (игроке, напарниках, призывах игрока, призывах NPC, врагах, квестовых NPC):
  * Коллизии: `SCF_PassThroughFriends`, `SCF_PassThroughAll`
  * Угроза / выбор цели врагами: `SCF_Untargetable`, `SCF_HighThreat` (`SCF_TauntPriority`), `SCF_LowThreat`
  * Дружественный огонь: `SCF_FriendlyFireProtected`, `SCF_AllowFriendlyFire`
  * Авторегистрация: `SCF_AutoRegister`
* **Summon (кейворды суммонов)** — применяются ко всем отслеживаемым SCF призывам игрока (ванильные призывы, реанимации / Dead Thrall, скриптовые призывы из `SCF.RegisterSummon`, а также актёры с `SCF_AutoRegister`).

## 3. Полный справочник кейвордов

### Группа 1. Коллизии и прохождение сквозь тела (`World`)

Работают независимо от настроек `[Collision]` в `SummonControlFramework.ini`. Отключают только столкновение капсул (`bhkCharacterController`) и обход в навигации (`MovementAvoidanceManager`); удары оружия, снаряды и геометрия мира не затрагиваются.

| EditorID | Алиасы | Область | Эффект |
|---|---|---|---|
| `SCF_PassThroughFriends` | — | World | Актёр свободно проходит сквозь «свою сторону» (общий лидер: игрок + напарники + все их призывы; у призыва NPC лидер — призвавший NPC) и не обходит их при поиске пути. |
| `SCF_PassThroughAll` | — | World | Актёр проходит сквозь **всех** актёров, включая врагов и нейтральных NPC. |

---

### Группа 2. Угроза и выбор цели врагами (`World`)

Управляют хуками `CombatGate` (`Actor::StartCombat` и `CombatTargetSelector::SelectTarget`) на стороне врагов.

| EditorID | Алиасы | Область | Эффект |
|---|---|---|---|
| `SCF_Untargetable` | — | World | Враги не могут выбрать актёра целью (`StartCombat` отклоняется, селектор перенаправляет на другую цель группы; если других целей нет — враг выходит из боя). Враги также проходят сквозь него физически. |
| `SCF_HighThreat` | `SCF_TauntPriority` | World | Провокация / танк. Враги, у которых этот актёр присутствует в боевой группе (жив и не потерян), принудительно выбирают его целью вместо обычных целей (включая игрока). Если в группе несколько `SCF_HighThreat`, враг выбирает ближайшего и придерживается уже выбранного танка (stickiness). |
| `SCF_LowThreat` | — | World | Пониженный приоритет угрозы (для хилеров, тотемов, саппортов). Враги предпочитают любую обычную цель, но переключатся на актёра с `SCF_LowThreat`, если других допустимых целей в группе не осталось. |

---

### Группа 3. Дружественный огонь (`World`)

Переопределяют защиту от дружественного огня во **всех пяти** точках SCF: ближний бой (`HitHook`), Precision melee pass-through (`PrecisionBackend`), стрелы и магические снаряды (`ProjectileHook`), AoE/заклинания (`MagicHook`), добивания и стаггер (`KillmoveHook`, `HitReactionHook`).

| EditorID | Алиасы | Область | Эффект |
|---|---|---|---|
| `SCF_FriendlyFireProtected` | — | World | Принудительно включает защиту актёра от атак, стрел, снарядов и AoE-заклинаний игрока, его напарников и союзных призывов — даже если актёр не зарегистрирован как суммон (например, скриптовый питомец, хрупкий квестовый NPC или нестандартный тотем). |
| `SCF_AllowFriendlyFire` | — | World | Принудительно **разрешает** дружественный огонь по этому актёру (даже если это призыв игрока и в INI включена глобальная защита `[FriendlyFire]`). Полезно для суммонов-«бочек», кристаллов детонации или механик жертвоприношения. |

---

### Группа 4. Жизненный цикл, регистрация, лимит и персистентность

| EditorID | Алиасы | Область | Эффект |
|---|---|---|---|
| `SCF_AutoRegister` | — | World | Автоматически регистрирует **любого** живого загруженного не-игрового актёра в реестре SCF как скриптовый призыв игрока (эквивалент `SCF.RegisterSummon`, но без Papyrus). Не занимает слот колдовства, подчиняется приказам, формации, панели миньонов и правилам SCF. Как только кейворд исчезает (например, закончился бафф) или актёр умирает, регистрация автоматически снимается. |
| `SCF_Unmanaged` | `SCF_IgnoreSummon` | Summon / World | Полное исключение из SCF. Фреймворк игнорирует этот призыв (не регистрирует в реестре, не перехватывает `StartCombat`, движение, приказы и реанимацию). Идеально для сложных скриптовых суммонов сторонних модов со своим AI. Перекрывает `SCF_AutoRegister`. |
| `SCF_FreeSlot` | `SCF_IgnoreLimit` | Summon / MGEF | Призыв **не занимает слот лимита колдовства**, не вытесняет уже активных суммонов при касте и сам никогда не вытесняется лимитом. Для предотвращения вытеснения движком вешайте на `MGEF` заклинания призыва (дополнительно можно на `NPC_`). |
| `SCF_Persistent` | — | Summon / MGEF | Индивидуально включает персистентность (PoE2 M4: обновление длительности и авто-возрождение при гибели) для этого призыва — **даже если глобально `bPersistentSummons = false`**. (Соблюдает чёрный список `Persistence` и проверку на ванильные/модовые заклинания.) |
| `SCF_NoPersistence` | — | Summon / MGEF | Индивидуально запрещает персистентность для этого призыва — **даже если глобально `bPersistentSummons = true`**. Идеально для временных ультимативных или взрывных суммонов. |

### Группа 5. Боевой режим, приказы, ассист, скрытность и поведение в бою (`Summon`)

| EditorID | Алиасы | Область | Эффект |
|---|---|---|---|
| `SCF_NonCombat` | `SCF_AlwaysPassive` | Summon | Жёстко мирный суммон (аура-баффер, светлячок, носильщик, декор). Навсегда фиксируется в `Passive`, `CombatPolicy` запрещает вход в бой и выключает атаки/касты, все приказы атаки (`Attack`/`SetFocusTarget`), `CommandAction` и смены агрессии на не-`Passive` отклоняются. Приказы движения (`Follow`, `WaitGuard`, `MoveTo`) продолжают работать. |
| `SCF_DefaultPassive` | — | Summon | При первом появлении призыва однократно устанавливает стартовый режим агрессии `Passive` (игрок может позже переключить режим вручную). |
| `SCF_DefaultDefensive` | — | Summon | При первом появлении однократно устанавливает стартовый режим агрессии `Defensive`. |
| `SCF_DefaultAggressive` | — | Summon | При первом появлении однократно устанавливает стартовый режим агрессии `Aggressive`. |
| `SCF_IgnoreOrders` | — | Summon | Игнорирует **все** приказы игрока и тактические команды (`Follow`, `Return`, `WaitGuard`, `MoveTo`, `Attack`, `SetAggression`, `CommandAction`). Принимаются только события жизненного цикла (`Lifecycle`) и `Dispel`. |
| `SCF_IgnoreHold` | — | Summon | Игнорирует приказ «Держать позицию» (`WaitGuard`). |
| `SCF_IgnoreFollow` | — | Summon | Игнорирует приказы «Следовать» и «Вернуться» (`Follow` / `Return`). |
| `SCF_IgnoreAttackOrder` | — | Summon | Игнорирует приказы атаки («В атаку» / `SetFocusTarget`, `Attack` и `CommandAction`). |
| `SCF_NoAssist` | — | Summon | Отключает автоматический ассист по целям, которые ударил игрок (`[Combat] bAssistPlayerAttacks`). Явный приказ «В атаку» (`PlayerDirect`) продолжает работать. |
| `SCF_NoCircling` | `SCF_DirectAssault` | Summon | Блокирует тактические манёвры кружения/отхода (`WolfManeuver`: `Circle`, `Surround`, `Flank`, `Fallback`, `Backoff`, `WatchTarget` и др.) **в любом бою**, а не только при явном приказе «В атаку». Заставляет ближних бойцов идти в прямой штурм. |
| `SCF_HoldFireInStealth` | — | Summon | Когда игрок крадётся и **не обнаружен**, призыв автоматически подавляет бой и держит атаки выключенными (в любом режиме агрессии, включая `Aggressive`). Прерывается, если игрока обнаружили или игрок отдал явный приказ «В атаку». |
| `SCF_IgnoreCombatRadius` | — | Summon | Полностью отключает ограничение радиуса агрессии (`[Combat] fAggressionRadius`), зону `SummonCombatRadius` (`aaMZkw_SummonCombatArea*`) и `SCF_CombatRadius_<N>` для этого призыва. |

### Группа 6. Специализации авто-выбора целей (`Summon`)

Переписывают автоматический выбор цели в `CombatTargetSelector` (когда у призыва **нет** явного приказа `FocusTarget` от игрока и нет активного пина `SummonCombatRadius`). Если текущая цель движка уже соответствует специализации, цель сохраняется (stickiness), чтобы не было метания между врагами.

| EditorID | Алиасы | Область | Эффект |
|---|---|---|---|
| `SCF_Bodyguard` | — | Summon | **Телохранитель.** Приоритет №1 — враги, атакующие владельца (ближайший к игроку); приоритет №2 — любой враг в радиусе **500 ед.** вокруг игрока (`kBodyguardAlertRadius`). Также `StartCombat` в режиме `Bodyguard` пропускает проверку `fAggressionRadius` против врагов, атакующих владельца. |
| `SCF_FinishLowHP` | — | Summon | **Добиватель.** Приоритетно выбирает врага со здоровьем **≤ 35%** (`kFinishLowHpThreshold = 0.35`, с минимальным HP%; смена уже выбранной раненой цели происходит только если другой враг ниже по HP более чем на 5%). |
| `SCF_HuntCasters` | — | Summon | **Охотник на магов.** Приоритетно выбирает ближайшего врага, который сейчас кастует заклинание или держит активное заклинание/посох в руках. |
| `SCF_HuntRanged` | — | Summon | **Охотник на стрелков.** Приоритетно выбирает ближайшего врага с экипированным луком, арбалетом или боевым посохом. |

### Группа 7. Движение, стойка, строй, поводок и телепорт (`Summon`)

| EditorID | Алиасы | Область | Эффект |
|---|---|---|---|
| `SCF_Stationary` | `SCF_Turret` | Summon | **Стационарная турель / тотем.** Призыв навсегда удерживает позицию (`HoldPosition`, `SetDontMove(true)`), отпускает ванильный поводок следования, пропускает сближение `AttackApproach` (при этом по явному приказу «В атаку» всё равно получает `StartCombat(focus)` и стреляет/кастует по фокусу с места). Команды `MoveTo` и `Return` отклоняются; догоняющий телепорт отключён. |
| `SCF_NoCatchUpWarp` | — | Summon | Отключает аварийный догоняющий телепорт SCF (`enableCatchUpWarp = false`) для этого призыва. |
| `SCF_NoCombatLeash` | — | Summon | Отключает боевой поводок SCF (`enableCombatLeash = false`): призыв не прерывает бой, если игрок убежал далеко. |
| `SCF_FormationFront` | `SCF_RoleTank` | Summon | Ставит призыв в **авангард (перед игроком)** при следовании (`+Y` в локальной системе игрока). |
| `SCF_FormationFlank` | `SCF_RoleMelee` | Summon | Ставит призыв на **фланги (слева и справа от игрока)** при следовании. |
| `SCF_FormationBack` | `SCF_RoleRanged`, `SCF_RoleSupport` | Summon | Ставит призыв в **арьергард (позади игрока)** при следовании (`-Y`). |

> **Как делятся слоты строя:** если в отряде есть суммоны разных ролей (например, 1 танк `Front`, 2 милишника `Flank`, 2 мага `Back`), каждый сектор получает собственную независимую нумерацию слотов `0..N-1`, поэтому сектора не смещают друг друга и суммоны выстраиваются в читаемый тактический строй вокруг игрока.

### Группа 8. Командные действия PoE2 M3 (`Summon`)

Переопределяют действие при нажатии командного действия отряда (M3), не требуя записи в `SummonControlFramework_Commands.ini`.

| EditorID | Алиасы | Область | Эффект |
|---|---|---|---|
| `SCF_CmdRush` | — | Summon | Командное действие для призыва — **Рывок (`Rush`)**: фокус на цели + временный бонус к скорости. |
| `SCF_CmdDetonate` | — | Summon | Командное действие для призыва — **Детонация (`Detonate`)**: если в каталоге M3 задано заклинание взрыва — кастует его, иначе мгновенно детонирует/убивает призыва (`KillImmediate`) и завершает эффект. |

### Группа 9. Параметрические числовые кейворды (`SCF_<Param>_<N>`)

Позволяют задавать точные числовые параметры **любым целым положительным числом `<N>`** (до 7 цифр, регистр не важен) прямо в имени `EditorID` записи `KYWD`. Некорректные суффиксы (`0`, отрицательные числа, буквы) безопасно игнорируются.

| Шаблон EditorID | Диапазон (clamp) | Правило слияния нескольких кейвордов | Эффект |
|---|---|---|---|
| `SCF_CombatRadius_<N>` | `50 .. 10000` | Побеждает **наименьшее** положительное | Персональный радиус автоматической боевой зоны (работает через движок `CombatRadius`, совместим с `SummonCombatRadius`). Пример: `SCF_CombatRadius_350`, `SCF_CombatRadius_800`. |
| `SCF_Leash_<N>` | `100 .. 20000` | Побеждает **наименьшее** положительное | Персональный радиус боевого поводка (`combatLeashRadius`, принудительно включает `enableCombatLeash = true`, если не стоит `SCF_NoCombatLeash`). Пример: `SCF_Leash_900`. |
| `SCF_FollowDist_<N>` | `60 .. 2000` | Побеждает **наименьшее** положительное | Персональная дистанция следования (`followMinDistance = N`, `followMaxDistance` масштабируется пропорционально, минимум `N + 50`). Пример: `SCF_FollowDist_120`, `SCF_FollowDist_450`. |
| `SCF_SpeedMult_<N>` | `25 .. 400` (%) | **Мультипликативное** перемножение: `(A × B) / 100`, с клампом в `[25, 400]` | Множитель темпа следования (`followWalkSpeed`, `followRunSpeed`, `sprintSpeed` умножаются на `N / 100`, с итоговым клампом `[25, 500]`). Пример: `SCF_SpeedMult_135` (+35% скорости), `SCF_SpeedMult_70` (-30%). |

## 4. Таблица приоритетов и разрешения конфликтов

Если на одном актёре (через `NPC_`, `RACE`, активные `MGEF` и исходный `MGEF` призыва) одновременно оказалось несколько конфликтующих кейвордов, SCF применяет **строго детерминированные правила**:

| Категория | Правило приоритета (слева — выше) |
|---|---|
| **Регистрация** | `SCF_Unmanaged` > `SCF_AutoRegister` > стандартный roster движка |
| **Выбор цели врагом (Threat)** | `SCF_Untargetable` (исключает из целей даже при `HighThreat`) > `SCF_HighThreat` > обычный актёр > `SCF_LowThreat` |
| **Специализация суммона** | Явный `FocusTarget` > `SCF_Bodyguard` > `SCF_FinishLowHP` > `SCF_HuntCasters` > `SCF_HuntRanged` > выбор движка |
| **Дружественный огонь** | `SCF_AllowFriendlyFire` > `SCF_FriendlyFireProtected` > базовая политика `[FriendlyFire]` |
| **Персистентность** | Чёрный список / невалидный тип (`false`) > `SCF_NoPersistence` (`false`) > `SCF_Persistent` (`true`) > глобальный `bPersistentSummons` |
| **Стартовая агрессия** | `SCF_NonCombat` / `SCF_DefaultPassive` > `SCF_DefaultDefensive` > `SCF_DefaultAggressive` |
| **Сектор строя** | `SCF_FormationFront` > `SCF_FormationFlank` > `SCF_FormationBack` > `Default` |
| **Боевой радиус** | `SCF_IgnoreCombatRadius` (`0` = без ограничения) > `min(SummonCombatRadius, SCF_CombatRadius_<N>)` |
| **Боевой поводок** | `SCF_NoCombatLeash` (отключён) > `SCF_Leash_<N>` > INI `fCombatLeashRadius` |
| **M3-командное действие** | `SCF_CmdDetonate` > `SCF_CmdRush` > `SummonControlFramework_Commands.ini` |
| **Приказы** | `Lifecycle` / `Dispel` (всегда принимаются) > `SCF_IgnoreOrders` > частные фильтры (`SCF_NonCombat`, `SCF_NoAssist`, `SCF_IgnoreHold`, `SCF_IgnoreFollow`, `SCF_IgnoreAttackOrder`, `SCF_Stationary`) |

## 5. Взаимодействие с Summon Combat Radius и INI-настройками

* **Совместимость с SCR (`aaMZkw_SummonCombatArea200/500/1000`):** если на призыве висят одновременно кейворд SCR (например, `500`) и `SCF_CombatRadius_300`, используется минимальный положительный радиус (`300`). Если на призыве стоит `SCF_IgnoreCombatRadius`, зона отключается полностью (`0`).
* **Персональные переопределения INI:** `SCF_FollowDist_<N>`, `SCF_Leash_<N>`, `SCF_NoCombatLeash`, `SCF_NoCatchUpWarp` и `SCF_SpeedMult_<N>` создают **персональную копию настроек на один тик** для конкретного призыва и никогда не портят глобальные настройки `SummonControlFramework.ini` для остальных членов отряда.
* **Явный приказ игрока всегда сильнее авто-боя:** кроме случаев, когда на призыве стоят `SCF_NonCombat`, `SCF_IgnoreOrders` или `SCF_IgnoreAttackOrder`, заклинание «Приказ: В атаку» (`SCF_CmdAttackTarget`) перебивает `SCF_HoldFireInStealth`, специализации и боевой радиус.

## 6. Готовые рецепты архетипов

| Архетип | Набор кейвордов | Результат в игре |
|---|---|---|
| **Танк-провокатор (Голем / Лорд Дремора)** | `SCF_RoleTank`, `SCF_HighThreat`, `SCF_Bodyguard`, `SCF_NoCircling`, `SCF_FollowDist_140` | Идёт впереди игрока, перетягивает врагов на себя, мгновенно перехватывает атакующих игрока и не кружит вокруг цели. |
| **Стационарная турель / тотем** | `SCF_Turret`, `SCF_NoCatchUpWarp`, `SCF_IgnoreFollow`, `SCF_CombatRadius_900` | Стоит на месте призыва, не телепортируется и не бежит на «Следовать», обстреливает врагов в радиусе 900 ед. и принимает фокус «В атаку». |
| **Дух-аура / саппорт-баффер** | `SCF_NonCombat`, `SCF_Untargetable`, `SCF_PassThroughAll`, `SCF_RoleSupport`, `SCF_FreeSlot` | Не тратит слот призыва, держится за спиной, проходит сквозь всех, враги его игнорируют, сам в бой не лезет. |

| **Взрывной миньон / камикадзе** | `SCF_NoPersistence`, `SCF_AllowFriendlyFire`, `SCF_CmdDetonate`, `SCF_NoCircling`, `SCF_SpeedMult_150` | Не возрождается персистентностью, его можно взорвать дружественным ударом или командой M3 (`Detonate`), бежит в лоб на +50% скорости. |
| **Магический снайпер (Атронах)** | `SCF_RoleRanged`, `SCF_LowThreat`, `SCF_FollowDist_320`, `SCF_HuntRanged` | Держится позади игрока на 320 ед., враги предпочитают бить танка/игрока, приоритетно снимает вражеских лучников. |
| **Спутник-питомец без слота** | `SCF_AutoRegister`, `SCF_FreeSlot`, `SCF_FriendlyFireProtected`, `SCF_PassThroughFriends` | Любой скриптовый питомец автоматически попадает под управление SCF, защищён от friendly fire и не занимает слот колдовства. |
| **Автономный скриптовый суммон мода** | `SCF_Unmanaged` | SCF полностью оставляет этого актёра в покое, не вмешиваясь в его собственный AI. |

## 7. Примеры раздачи через KID и SPID (без правки чужих ESP)

### Вариант A: Keyword Item Distributor (KID) — `Data/SCF_MyArchetypes_KID.ini`

Убедитесь, что нужные `KYWD` определены в вашем патче или в тестовом плагине `SCF_KeywordApiTest.esp`, после чего раздайте их по формам:

```ini
; Грозовой атронах — дальнобойный снайпер арьергарда с низким агро
Keyword = SCF_RoleRanged|Actor|EncAtronachStorm
Keyword = SCF_LowThreat|Actor|EncAtronachStorm
Keyword = SCF_HuntCasters|Actor|EncAtronachStorm
Keyword = SCF_FollowDist_300|Actor|EncAtronachStorm

; Лорд Дремора — фронтовой танк-провокатор, идущий в прямой штурм
Keyword = SCF_RoleTank|Actor|EncDremoraLord
Keyword = SCF_HighThreat|Actor|EncDremoraLord
Keyword = SCF_Bodyguard|Actor|EncDremoraLord
Keyword = SCF_NoCircling|Actor|EncDremoraLord

; Фамильяр-волк — не занимает слот, не палит скрытность, быстрее на 30%
Keyword = SCF_FreeSlot|MagicEffect|SummonFamiliarFFSelf
Keyword = SCF_HoldFireInStealth|Actor|EncFamiliar
Keyword = SCF_SpeedMult_130|Actor|EncFamiliar
```

### Вариант B: Spell Perk Item Distributor (SPID) — `Data/SCF_DynamicBuffs_DISTR.ini`

SPID удобен, когда вы хотите вешать **способность (`SPEL` типа `Ability`)** с `MGEF`, несущим кейворд — например, условно (только на уникальных NPC или при наличии перка):

```ini
; Повесить способность с SCF_FriendlyFireProtected и SCF_PassThroughFriends на всех питомцев фракции игрока
Spell = MyMod.esp|0x801|PlayerFaction|NONE|NONE|NONE|100
```

## 8. Генератор тестового плагина и диагностика в логах

### Тестовый ESP со всеми кейвордами API v2

В репозитории есть генератор [tools/make_keyword_test_esp.py](../tools/make_keyword_test_esp.py):

```powershell
python tools/make_keyword_test_esp.py "<путь к Skyrim.esm>" SCF_KeywordApiTest.esp
```

Он создаёт ESL-плагин `SCF_KeywordApiTest.esp`, содержащий все 40 записей `KYWD` Keyword API v2 (включая примеры параметрических кейвордов `SCF_CombatRadius_500`, `SCF_Leash_800`, `SCF_FollowDist_250`, `SCF_SpeedMult_140`), а также для каждого кейворда:
* заклинание `SCF Test: <Имя>` (120 с, на цель — для быстрой проверки в бою);
* постоянную способность `SCF Test Ability: <Имя>` (для `addspell` / `removespell` через консоль).

### Диагностика в `SummonControlFramework.log`

* При загрузке (`kDataLoaded`):
  ```text
  [KeywordApi] Loaded N keyword record(s) (world active=yes|no, summon active=yes|no)
  ```
* Если плагинов с `SCF_*` нет:
  ```text
  [KeywordApi] 0 API keyword record(s) found in load order; idle
  ```
* В бою и при работе фильтров:
  * `[CombatGate] ... SCF_Untargetable ...` — отказ `StartCombat` или выход из боя против `SCF_Untargetable`.
  * `[UpdateHook]` — логи авторегистрации (`SCF_AutoRegister`), пропуска (`SCF_Unmanaged`) и стартовой агрессии (`DefaultAggressionFromKeywords`).
  * `[SummonLimit]` — пропуск лимита при касте заклинания с `SCF_FreeSlot`.
